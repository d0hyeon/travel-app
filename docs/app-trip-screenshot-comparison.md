# 여행 상세 화면 웹·앱 스크린샷 대조 기록

기준일: 2026-08-21

## 검증 환경

- 웹: `http://localhost:5173`, 여행 ID `99ae4c6d-57aa-4835-9069-35680a687689`, viewport 393×852
- 앱: Expo 번들러 `localhost:8082`, iPhone 17 Simulator
- 동일 계정과 동일 여행 데이터를 사용했다.
- 웹의 장소·계획 탭은 Kakao Maps SDK가 로드되지 않아 `undefined.maps` 오류가 발생했다. 이는 앱 구현 차이로 판정하지 않고 웹 검증 환경 이슈로 기록한다.

## 수정 완료

- 상세 콘텐츠의 `height: 100%`를 `flex: 1`로 변경해 하단 네비게이션이 화면 밖으로 밀리던 문제를 수정했다.
- 앱 상세 헤더에 웹과 동일한 뒤로가기·제목 수정·채팅 액션을 추가하고 스크린샷으로 재검증했다.

## 확인된 앱 런타임 경고

상세 진입 직후 `Can't perform a React state update on a component that hasn't mounted yet` 경고가 반복 노출된다. 화면 기능 비교와 별도로 suspense/query 초기화 경로를 추적해야 한다.

## 다음 대조 대상

- 장소 탭: 장소 검색·필터·장소 추가·장소 상세 및 지도
- 계획 탭: 날짜 선택 UI, 경로 생성·삭제, 경로 순서 변경(낙관적 업데이트 제외)
- 정산 탭: 목록/장소 전환, 지출 추가 폼, 경로 기반 지출, 정산
- 사진 탭: 전체 필터, 업로드, 사진 상세, 장소 연결, 공개 전환, 삭제

## 정산 탭 상세 시나리오 대조

### 일반 지출 추가

웹 시나리오: `정산` → `지출 추가` → 결제자 선택 → 금액 입력 → 내용 입력 → 날짜 입력 → 장소 선택 → 나눠 낼 사람 선택 → 취소/저장.

앱도 동일한 입력 항목을 제공하도록 날짜 입력과 웹 순서 기준을 반영했다. 폼 제출은 기존 도메인 `create` 흐름을 사용한다.

### 경로 기반 지출

웹 시나리오: `정산` → `경로 기반` → 지도 미리보기 → 일차별 장소 목록 → 장소별 지출 추가.

기존 앱은 지도·빈 일차·장소별 추가 액션이 빠져 있었으나 다음을 반영했다.

- Google 지도 미리보기와 경로 장소 마커
- 지출이 없는 일차도 일차 헤더와 0원 표시
- 각 장소별 지출 추가 버튼과 일반 지출 폼 연결

실제 검증 완료: 첫 장소 `강토탈 속초역주유소`에서 웹과 앱 모두 지출 추가 폼을 열고 `경로 테스트 지출`, `10,000원`, `6/1`을 입력해 저장했다. 저장 후 장소별 금액·지출 건수·일차 합계가 양쪽에 표시되는 것을 확인했다. 이후 나머지 장소의 추가 버튼 4개는 각각 폼 진입과 취소까지 순회했다.

## 발견 후 수정한 플로우 버그

- 하단 탭 전환 시 현재 여행 ID 파라미터가 누락되던 문제를 수정했다.
- 공용 내부 탭의 `onLayout` 상태 갱신이 화면 전환 후 실행되던 오류를 제거했다.
