# 앱 여행 상세 UI 정의서

웹 모바일 화면을 시각적 기준으로 삼는다. RN에서는 컴포넌트 표현만 native로
바꾸고, 정보 구조·순서·문구·상태·간격·색상·인터랙션은 동일하게 유지한다.

## 공통

- 화면은 상단 여행 헤더, 콘텐츠, 하단 5개 탭 구조다.
- 탭 순서는 `정보 / 장소 / 계획 / 정산 / 사진`이며 아이콘은 각각 info,
  pin-drop, near-me, receipt, photo 의미를 유지한다.
- 콘텐츠 전환 시 탭 셸 전체가 재마운트되지 않아야 하며 로딩 상태를
  콘텐츠 영역 안에서 처리한다.
- 여행 상세 상단에는 여행 이름을 표시하고 탭해서 이름 수정 바텀시트를 연다.
- 바텀시트의 스냅 포인트는 기본 50%, 25/50/80/100%다.

## 탭별 기준

- 정보: 내부 3탭(`기본정보 / 체크리스트 / 메모`), 기본정보는 D-Day → 회고
  카드(종료 여행) → 여행 정보 → 해야 할 일 → 고정 메모 → (2단계 콘텐츠)
  → 멤버 → 나가기 순서다.
- 장소: Google 지도를 전체 배경으로 사용하고 바텀시트가 겹치며 `확정 (n) / 후보 (n)` 헤더와 장소
  목록, 하단 고정 `장소 추가` 버튼을 둔다.
- 계획: 지도와 바텀시트, 날짜 선택, 경로 선택, 정렬 목록, 장소별 액션·메모,
  하단 `장소 추가` 버튼을 둔다.
- 정산: 총 지출 헤더 → `지출 내역 / 정산` 내부 탭 → 콘텐츠 → 하단
  `경로 기반 / 지출 추가` 액션 구조다.
- 사진: 상단 고정 장소 필터와 선택/완료 칩, 3열 사진 그리드, 선택 모드의
  하단 삭제 액션, 사진 상세 바텀시트를 둔다.
