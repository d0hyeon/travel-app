# 한국공항공사 운항 상태 provider와 도착 시각 표시 정책

`2026-10-03-flight-status-departure-only-and-arrival-estimate-design.md`의 후속 설계다. 그 문서의 "도착 시각 = 입력값 + 출발 지연 분" 추정을 폐기하고, 한국공항공사 소관 국내선 운항 상태를 추가한다. 기존 문서는 수정하지 않는다.

## 배경

### 도착 시각 추정이 틀리는 근거

한국공항공사 API로 김포·부산·제주 구간에서 출발·도착을 모두 마친 583편을 비교했다(2026-10-03 실측).

| | 평균 |
|---|---|
| 출발 지연 | 25.9분 |
| 도착 지연 | 5.4분 |
| 도착지연 − 출발지연 | −20.5분 (583편 중 572편이 5분 넘게 덜 늦음) |

항공사가 시간표에 여유를 두고 비행 중 만회하기 때문이다. 출발 지연을 그대로 도착에 더하는 추정은 이 구간에서 도착을 평균 20분 늦게 보여준다. 인천발 국제선은 목적지 도착 시각을 주는 API가 없어 같은 규칙인지 검증할 수 없다.

### 한국공항공사 API (공공데이터포털 `flight-status`, 실측)

- 기준 URL: `https://apis.data.go.kr/B551178/flight-status`. 필수값은 서비스 키뿐이다. 한 페이지 최대 100건(`numOfRows`), 기본 10건.
- `/depart`·`/arrival`: 공항(`airport_code`)·날짜(`searchday`)·시간대(`from_time`·`to_time`, 계획 시각 기준) 조건으로 조회. 날짜 범위 D-3~D+6. 기준 공항 쪽 예정·변경 시각(`scheduledatetime`·`estimateddatetime`, `YYYYMMDDHHMM`)과 상태(`rmkKor`)를 준다. 게이트·터미널은 없다.
- `/detail`: 14개 공항 3일치(어제~내일) 전량, 게이트·수하물 수취대 포함. 파라미터가 없어 호출 비용이 크다(54페이지).
- `/info`: 공항별 오늘 스냅샷, 게이트 포함, 날짜 필드 없음.
- 터미널 필드는 어느 오퍼레이션에도 없다.
- 공항 14곳: CJU, GMP, PUS, CJJ, TAE, KWJ, USN, HIN, RSU, KPO, KUV, YNY, WJU(데이터에서 확인된 13곳)와 인천(국내선 7~8편만).
- 한 편이 출발 공항의 `/depart`와 도착 공항의 `/arrival`에 따로 나온다. 짝짓는 키는 `masterflightid ?? flightid`와 날짜다(`fid`는 공항마다 달라 쓸 수 없다). 코드셰어 편명(KE5153)은 `masterflightid`(LJ501)로 짝이 맞는다.
- 상태: `출발`, `도착`, `착륙`, `수속중`, `마감예정`, `탑승중`, `탑승장 입장`, `탑승마감`, `탑승구 변경`, `지연`, `결항`, `사전결항`. `사전결항`은 편명 묶음 전체가 같은 시각으로 미리 취소된 편이다. `지연` 중에는 변경 시각이 예정 시각과 같은 행이 있다.

## 결정

1. **인천 출발편의 도착 시각은 입력값 그대로 둔다.** 시각을 바꾸지 않고, 출발이 지연됐으면 "출발이 N분 지연돼 도착이 늦어질 수 있어요" 문구만 보여준다.
2. **한국공항공사 소관 공항에서 출발하는 편도 운항 상태를 감시·저장한다.** 인천 API와 같은 `trip_transport_flight_status` 행으로 정규화한다. 클라이언트는 행만 읽는다.
3. **도착 공항도 한국공항공사 소관이면 `/arrival`에서 도착 예정·변경 시각을 가져와 행에 저장하고, 화면은 그 값을 쓴다.** 이 경우 지연 문구는 보이지 않는다(실제 시각이 있다).
4. 한국공항공사 소관 국제선의 해외 쪽 도착 시각은 인천 API와 같은 한계로 처리한다(입력값 + 출발 지연 문구).
5. **상태 정규화**
   - `결항`, `사전결항` → 결항
   - `회항` → 회항
   - `지연` → 변경 시각이 예정 시각보다 늦을 때만 지연. 같으면 예정(분 수를 말할 수 없는 지연 알림을 막는다)
   - `출발` → 출발. 도착 목록에서 짝이 `도착`이면 도착
   - 그 밖(수속·탑승 진행 상태, `탑승구 변경`, 비어 있음) → 예정
6. **조회 창과 관측 주기를 좁힌다.** 호출 한도(개발 계정 일 5,000회)를 지키려고 출발 시각 전후 2시간(시 단위)만 `/depart`로 받고, 도착 목록은 출발 시각부터 5시간 구간만 받는다. 같은 조건의 목록은 한 번만 받는다. 감시 함수는 5분마다 돌지만 한국공항공사 편은 출발까지 남은 시간에 따라 관측 주기를 달리한다(`getObserveIntervalMinutes`): 출발 3시간 이내 5분, 3~24시간 전 15분, 24시간보다 먼 편 3시간, 이미 출발한 편(도착 확인)은 15분. 편마다 조회 창이 달라 호출이 편 수에 비례하므로 이 차등이 필요하다.
7. **터미널은 저장하지 않고, 게이트는 후속 설계(`2026-10-03-korea-airports-gate-design.md`)에서 `/info`로 저장한다.** 터미널은 어느 오퍼레이션에도 없어 비어 있고 탑승권 입력값이 표시된다. 게이트는 `/depart`·`/arrival`에 없어 이 문서의 초안에서는 저장하지 않았으나, 이후 `/info`의 오늘 스냅샷을 (편명, 예정 시각 HHMM)으로 짝지어 저장하도록 바뀌었다. 게이트 변경 알림도 그 설계에서 켠다.
8. 지원 공항 안내 문구("… 출발 항공편에 한해 지원돼요")는 지원 공항이 늘어도 읽히도록 쉼표로 이어 붙인다.

## 이전과 이후

| | 이전 | 이후 |
|---|---|---|
| 감시 대상 | 인천 출발 | 인천 + 한국공항공사 13개 공항 출발 |
| 조회 가능 기간 | D+0~D+6 | 인천 D+0~D+6, 한국공항공사 D-3~D+6 |
| 도착 시각 | 입력값 + 출발 지연 | 입력값(인천발) / API 시각(한국공항공사 도착) |
| 지연 표시 | "지연 반영" 캡션과 변경된 시각 | "출발이 N분 지연돼 도착이 늦어질 수 있어요" 문구 |
| `trip_transport_flight_status` | 출발 시각만 | 도착 예정·변경 시각 컬럼 추가(널 허용) |

## 영향과 한계

- 짝지을 때 사용자가 입력한 출발 시각이 실제와 2시간 넘게 다르면 조회 창에서 벗어나 편을 못 찾는다. 상태가 비는 것으로 끝나고 오표시는 없다.
- 호출 비용은 대상 편(공항·시간대) 수에 비례한다. 편 하나가 목록 조회를 출발 목록 1회 + 도착 목록 1회씩 부르므로 일생 동안 약 370회(먼 구간 3시간 주기 80, 24시간 전~3시간 전 15분 주기 168, 3시간 이내 5분 주기 72, 출발 후 6시간 15분 주기 48)다. 시간대가 겹치는 편은 목록을 공유하므로 이보다 적다. 공유가 없다고 보면 개발 계정(일 5,000회)은 하루 출발 약 13편이 한계다. 넘기려면 운영 계정 확대 신청이 필요하다. 한도를 넘으면 한국공항공사 편의 갱신만 멈추고(조회 실패는 로그만 남기고 격리) 인천 감시는 영향이 없다.
- 푸시 지연·결항 알림도 이 주기에 묶인다. 출발 3~24시간 전 편은 최대 15분, 그보다 먼 편은 최대 3시간 늦게 감지한다.
- 자정을 넘겨 도착하는 편(예: 22시 출발, 00시 30분 도착)은 도착 목록 조회 창이 출발일 안에서 끝나 도착 시각을 못 찾는다. 입력값이 그대로 쓰이는 안전한 쪽으로 실패한다.
- 한국공항공사 소관 편의 게이트는 당일(`/info` 스냅샷) 편만 얻는다. 먼 날짜 편은 게이트가 비어 있다.
- 데이터 갱신 주기는 문서에 없다. 호출 시점 몇 분 전에 생성된 값(`fgenTime`)이라 거의 실시간으로 보인다.

## 검증 기준

- 상태 정규화 규칙(위 5번)이 테스트로 고정된다.
- 같은 편이 코드셰어 편명으로 등록돼도 도착 목록의 짝을 찾는다.
- 도착 목록에 짝이 없으면 도착 시각은 비고, 화면은 입력값을 쓴다.
- 인천발 지연 편은 도착 시각이 바뀌지 않고 지연 문구만 나온다.
- 한국공항공사 소관 도착 편은 API 도착 시각을 보여주고 지연 문구는 나오지 않는다.
- 한 공급원의 조회 실패가 다른 공급원의 감시를 막지 않는다.
