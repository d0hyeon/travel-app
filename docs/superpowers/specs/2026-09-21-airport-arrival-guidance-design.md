# 공항 도착 안내 설계

## 목표

저장된 출발 항공편에 대해 사용자가 공항 건물에 도착할 권장 시각을 안내한다. 집·숙소에서 출발할 시각이나 탑승 시작 시각은 판단하지 않는다.

안내는 항공편의 예정·변경 출발 시각, 터미널, 공항별 혼잡 데이터를 함께 사용한다. 화면과 푸시는 각각 필요한 시점에 외부 API를 조회할 수 있지만, 대상 판단·혼잡 등급·권장 시각 계산에는 하나의 정책을 사용한다.

## 범위

### 포함

- 터미널이 입력된 해외·국내 출발 항공편의 공항 도착 권장 시각
- 해외편의 예고 여객 데이터와 실시간 출국장 혼잡도에 근거한 안내
- 국내편의 한국공항공사 공항 혼잡도에 근거한 안내
- 교통편 상세와 여행 기본정보 탭의 동일한 판단 노출
- 해외 출발편의 D-1 18:00(Asia/Seoul) 푸시
- 항공편 생성·수정·삭제에 대응하는 푸시 작업 예약·취소

### 제외

- 집·숙소 출발 시각, 공항버스·주차·택시 추천
- 탑승구까지의 실내 길찾기와 실내 지도
- 국내선 푸시
- 터미널이 없는 항공편의 안내·푸시
- 혼잡 데이터 갱신에 따른 푸시 재발송
- 탑승 시작 시각을 단정하는 안내

## 데이터와 적용 시점

| 대상 | 데이터 | 용도 |
| --- | --- | --- |
| 해외 출발편 | 인천국제공항공사 승객예고-출·입국장별 API | 권장 도착 시각 계산, D-1 18:00 푸시 |
| 해외 출발편 | 인천 T1·T2 실시간 출국장 혼잡도 API | 사용자의 권장 도착 시각이 가까워진 뒤, 현재 더 여유로운 출국장 추천 |
| 국내 출발편 | 한국공항공사 공항 혼잡도 API | 권장 도착 시각 계산 |
| 모든 항공편 | 기존 flight-status | 변경 출발 시각·결항 여부 |

인천 승객예고 API는 조회일과 다음 날(D+0, D+1)만 제공한다. 따라서 해외편 푸시는 출발 전날 18:00에 발송한다. 이 API가 제공하는 값은 시간대별 예상 승객 수이며, 예상 혼잡도 안내에 필요한 문구·출처 표기는 제공기관 가이드를 따른다.

실시간 출국장 대기 인원은 미래의 권장 도착 시각을 예측하는 근거로 사용하지 않는다. 사용자가 실제로 공항에 도착할 시각이 가까워진 뒤에만 현재 출국장 추천에 사용한다.

## 도착 권장 시각 정책

기본 여유 시간은 국내선 120분, 국제선 180분이다. 혼잡도는 출국장별 원본 승객 수를 해당 출국장의 기준 승객 수로 나눈 비율로 분류한다. 예고 데이터와 실시간 데이터는 단위가 다르므로 각각 별도의 기준 승객 수를 가진다.

| 혼잡 비율 | 등급 | 추가 여유 |
| --- | --- | ---: |
| 50% 이하 | 여유 | 0분 |
| 50% 초과, 75% 이하 | 보통 | 15분 |
| 75% 초과, 100% 이하 | 혼잡 | 30분 |
| 100% 초과 | 매우 혼잡 | 45분 |

```text
혼잡 비율 = 출국장 승객 수 / 출국장별 기준 승객 수

권장 공항 도착 시각
= 적용 출발 시각
- 항공편 기본 여유 시간
- 가장 혼잡한 출국장의 추가 여유 시간
```

지연으로 변경 출발 시각이 있으면 이를 적용 출발 시각으로 사용한다. 결항, 출발 시각 경과, 터미널 미입력, 혼잡 데이터 부재·조회 오류 때는 공항 도착 안내를 만들지 않는다.

## 정책과 캐시

운영 정책은 코드 상수가 아니라 DB의 활성 공항 도착 안내 정책으로 관리한다. 정책은 국내·국제선 기본 여유 시간, 등급별 추가 여유 시간, 공항·터미널·출국장·데이터 종류별 기준 승객 수를 소유한다. 관리자는 직접 DB에서 정책을 조정한다.

외부 API 원본 응답은 공항 혼잡 스냅샷으로 저장해 화면과 푸시가 공유한다.

- 예고 데이터는 공항·터미널·날짜 단위로 저장한다.
- 실시간 데이터는 공항·터미널 단위로 짧은 만료 시간(1~5분)을 둔다.
- API 키는 엣지 함수의 비밀값으로만 보관한다.
- 사용자별 화면 응답은 CDN에 캐시하지 않는다. 개인 항공편 정보와 데이터 최신성을 고려해 공유 DB 캐시를 사용한다.

## 책임 경계

- 공항 혼잡 데이터 제공자: 외부 API를 조회하고 원본 데이터를 공통 형태로 정규화한다.
- 공항 혼잡 스냅샷: 데이터별 최신 원본 응답과 갱신 시각을 보관한다.
- 공항 도착 안내 판단: 대상 여부, 데이터 종류 선택, 정책 적용, 권장 시각·출국장 추천을 결정한다.
- 화면: 이미 결정된 결과를 상세·요약 밀도에 맞춰 표현한다.
- 예약 알림 작업: 예약·점유·재시도·취소·발송 결과만 관리한다. 혼잡 계산을 소유하지 않는다.
- 푸시 실행 엣지 함수: 실행 시점에 안내 판단 결과를 얻어 유효한 여행 멤버·구독자에게 발송한다.

## 화면 정책

### 교통편 상세

다음 정보를 표시한다.

- 권장 공항 도착 시각
- 항공편·터미널·적용 출발 시각
- 기본 여유와 혼잡 보정의 적용 이유
- 예고 또는 실시간 데이터라는 기준과 갱신 시각
- 해외편이 권장 도착 시각에 가까운 경우, 가장 여유로운 현재 출국장

국내선에는 출국장 추천을 표시하지 않는다.

### 여행 기본정보 탭

기존에 표시하는 항공편 카드에 도착 권장 시각만 추가한다. 별도 안내 카드나 별도 이동 동작을 만들지 않으며, 상세와 별도의 계산 규칙을 두지 않는다.

## 예약 푸시 정책

해외 출발편이 생성되거나 수정될 때마다 대상 여부를 다시 평가한다. 출발 공항·출발 시각·항공편 종류·항공사·편명뿐 아니라 터미널 변경도 예약 재평가 대상이다.

대상 조건을 만족하면 출발 전날 18:00(Asia/Seoul)에 `airport_arrival_guidance` 알림 작업을 예약한다. 터미널을 새로 입력하면 이때 예약할 수 있으며, 터미널 삭제·항공편 삭제·대상 이탈·결항은 아직 발송하지 않은 작업을 취소한다. 출발 시각 변경은 기존 작업을 취소하고 새 작업을 예약한다.

크론은 예약 시각에 푸시 실행 엣지 함수를 호출한다. 실행기는 최신 정책, D+1 예고 데이터, 운항 상태, 실행 시점의 여행 멤버십과 푸시 구독을 확인한다. 데이터 조회 실패, 결항, 유효 수신자 없음이면 푸시를 보내지 않는다. 오류는 5분·15분·30분 후 최대 세 번 재시도하고 이후 실패로 남긴다.

예약 작업은 다음 상태를 명시적으로 갖는다.

| 상태 | 의미 |
| --- | --- |
| `pending` | 예약됨, 아직 실행 전 |
| `processing` | 실행기가 점유해 처리 중 |
| `delivered` | 유효 수신자 발송 처리 완료 |
| `failed` | 재시도 한도를 넘긴 오류 |
| `cancelled` | 더 이상 발송할 이유 없음 |

작업은 여행이 아니라 알림 발송을 책임지고, 어떤 항공편의 변경으로 무효가 되었는지 알 수 있도록 교통편을 참조한다. 같은 항공편·알림 유형의 미완료 작업은 하나만 존재해야 한다.

## 구현 순서와 검증

구현은 아래 순서를 지키며, 모든 순수 정책·예약 규칙에는 설계 우선 TDD를 적용한다.

1. DB 테이블 모델과 마이그레이션을 만든다. 정책, 혼잡 스냅샷, 예약 알림 작업의 상태·유일성·권한을 먼저 확정한다.
2. 엣지 함수를 만든다. 공항 데이터 조회·캐시 갱신, 푸시 작업 실행·재시도·발송을 구현한다.
3. 크론 작업을 만든다. 예약된 D-1 18:00 작업과 재시도를 실행기에 전달한다.
4. 도메인·화면 코드를 만든다. 안내 판단 결과를 상세와 기본정보 탭에 연결한다.

각 순수 로직은 먼저 인터페이스와 `it.todo` 검증 케이스를 작성하고, 한 케이스씩 실제 테스트로 전환해 최소 구현으로 통과시킨다. UI 컴포넌트는 빌드와 실제 앱 확인으로 검증한다.

### 검증 기준

- 터미널 미입력·결항·출발 시각 경과·혼잡 데이터 부재에는 카드와 푸시가 없다.
- 해외편 푸시는 D-1 18:00에만 예약되며, D+1 예고 데이터로 계산한다.
- 국내선은 푸시를 예약하지 않고 한국공항공사 혼잡도 기반으로만 화면 안내를 만든다.
- 국내선 120분·국제선 180분과 혼잡 비율별 추가 여유가 활성 정책과 일치한다.
- 예고·실시간 데이터는 각자의 출국장 기준 승객 수로 분류된다.
- 실시간 데이터는 미래 도착 시각 계산이 아니라, 도착이 가까운 사용자의 출국장 추천에만 쓰인다.
- 상세와 기본정보 탭은 같은 항공편에 대해 같은 권장 도착 시각을 보여 준다.
- 항공편 생성·수정·삭제와 터미널 변경으로 예약 작업이 올바르게 생성·취소되며 중복이 없다.
- 발송 시점의 유효한 여행 멤버·푸시 구독자만 수신한다.
- 조회 실패는 세 번 재시도 후 실패로 남고 빈 푸시는 보내지 않는다.
