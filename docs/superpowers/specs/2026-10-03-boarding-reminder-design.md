# 탑승 전 알림

`docs/trip-transport-definition.md`의 "시간 기반 Push (2단계)" 방향을 구현하는 설계다. 그 문서는 "출발 전 알림, 구체적 시점은 UX 정책"까지만 정했고, 이 문서가 시점과 문구를 확정한다.

## 결정

1. **항공은 출발 30분 전, 기차·버스는 출발 10분 전에 푸시를 보낸다.** 항공은 보통 출발 20분 전부터 탑승을 시작하므로 30분 전은 "탑승 시작 10분 전"이다.
2. **문구**
   - 항공: 제목 `{항공사} {도착 도시}행 ({편명}편) 탑승 안내`, 본문 `탑승 시작 10분 전이에요. 탑승 준비를 마쳐주세요`
   - 기차·버스: 제목 `{출발지} → {도착지} 탑승 안내`, 본문 `출발 10분 전이에요. 탑승 준비를 마쳐주세요` (기차·버스에는 별도 탑승 시작이 없어 출발 기준으로 적었다)
3. **기준 시각**: 항공은 화면과 같은 순서로 운항 상태의 변경 출발 시각(`estimated_at`), 예정 시각(`scheduled_at`), 사용자가 입력한 출발 시각 중 먼저 있는 값. 기차·버스는 입력한 출발 시각.
4. 수신자와 발송 경로는 공항 도착 권장시간 푸시와 같다: 여행 멤버 전원의 푸시 구독, 탭하면 교통편 상세로 이동한다(`{tripId, transportId}`).
5. 예약 알림 스케줄러를 쓴다: `scheduled_notifications`에 `type = 'boarding_reminder'`로 예약하고, 크론 `dispatch-notifications`(매분)가 깨우는 디스패처가 종류별 핸들러로 보낸다. 스케줄러 구조는 `2026-10-03-scheduled-notifications-design.md`에 있다.
6. 예약은 DB 트리거가 만들고 취소한다.
   - 교통편 생성·수정·삭제, 운항 상태의 `kind`·`estimated_at` 변경 때 다시 계산한다(지연되면 새 시각으로 다시 예약, 결항이면 취소).
   - 예약 시각이 이미 지났으면 예약하지 않는다. 출발 30분(10분) 이내에 등록한 교통편에는 알림이 없다.
   - 발송 시점에 이미 출발했거나 결항이면 보내지 않는다.

## 이전과 이후

| | 이전 | 이후 |
|---|---|---|
| 시간 기반 푸시 | 공항 도착 권장시간(해외 인천 출발, 전날 18시) 하나 | + 탑승 전 알림(항공 30분, 기차·버스 10분) |
| 예약 알림 종류 | `airport_arrival_guidance` | + `boarding_reminder` |

## 영향과 한계

- 여행 멤버 전원이 받는다. 멤버마다 탑승 시각이 다른 경우(다른 교통편)는 교통편이 다르므로 해당하지 않는다.
- 발송은 크론이 매분 도는 주기에 맞아 최대 1분 늦을 수 있다. 실패하면 5·15·30분 뒤 재시도하는데, 재시도로 출발 후에 도착하면 보내지 않는다.
- 기차·버스는 실시간 정보가 없어서 입력한 출발 시각이 틀리면 알림 시각도 틀린다.

## 검증 기준

- 항공 본문은 "탑승 시작 10분 전", 기차·버스 본문은 "출발 10분 전"이다.
- 항공 제목에 항공사·도착 도시·편명이 있고, 편명이 없으면 편명 부분을 뺀다. 기차·버스 제목은 `출발지 → 도착지`다.
- 이미 출발했거나 결항인 교통편에는 보내지 않는다.
- 예약 시각이 지났으면 예약이 생기지 않고, 출발 시각이 바뀌면 새 시각으로 하나만 예약된다.
