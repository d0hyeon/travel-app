# 운항 상태: 인천 출발 한정과 도착 시각 지연 반영

`2026-10-03-airport-arrival-guidance-api-terminal-design.md`의 후속 설계다. 그 문서가 "후속에서 제거 예정"으로 남긴 인천 도착편 감시를 제거하고, 인천 API가 주지 않는 도착지 도착 시각을 지연 분으로 보정한다. 기존 문서는 수정하지 않는다.

## 배경

- 이 서비스는 인천 출발편만 대응한다. 그런데 `flight-status-watch`는 인천이 도착지인 편(해외→인천)도 감시했다.
- 도착편 경로는 `departure_at`(해외 출발 시각)을 인천 도착 목록의 `scheduleDateTime`(인천 도착 시각)과 같은 KST 날짜로 비교해 장거리에서 날짜가 갈린다. 감시 범위도 출발 시각 기준이라 인천 도착 시점과 어긋난다. 같은 컬럼(`scheduled_at`, `terminal`, `gate`)에 방향에 따라 출발·도착 의미가 섞인다.
- 인천 API(출발 목록)는 인천 출발 시각만 주고, 도착지 도착 시각은 주지 않는다. 명세의 "도착예정시간" 설명은 도착 목록 명세를 복사한 오류이며, 실데이터로 출발 시각임을 확인했다(`출발` 상태 91건이 모두 과거 시각).

## 결정

1. 감시와 클라이언트 조회 모두 **인천 출발편만** 대상으로 한다. 인천 도착편의 지연·결항·탑승구 알림과 운항 정보 카드는 사라진다(기능 제거).
2. 이미 저장된 인천 도착편의 운항 상태 행은 마이그레이션으로 지운다.
3. 도착지 도착 시각은 **사용자가 입력한 도착 시각 + 출발 지연 분**으로 추정한다.
   - 지연 분 = API 변경 시각 − API 예정 시각(둘 다 인천 API 값). 사용자가 출발 시각을 잘못 적어도 영향이 없다.
   - 지연일 때만(양수) 적용한다. 일찍 출발해도 도착을 당기지 않는다.
   - 결항·회항이면 적용하지 않는다.
   - 입력값을 덮어쓰되 추정임을 드러내려고 지연 분을 함께 돌려주고, 화면은 "지연 반영"을 표시한다.
   - 비행 중 만회나 추가 지연은 반영하지 못한다. 외부 항공 추적 API 없이 얻을 수 있는 근사치다.

## 이전과 이후

| | 이전 | 이후 |
|---|---|---|
| 감시 대상 | 인천 출발 또는 도착 | 인천 출발 |
| 인천 API 호출 | 출발·도착 목록 각 1회 | 출발 목록 1회 |
| 클라이언트 조회 가능 | 출발·도착 공항 중 인천이 있으면 | 출발 공항이 인천일 때 |
| 도착 시각 | 사용자 입력 그대로 | 지연이면 지연 분만큼 늦춰 표시 |

## 영향과 한계

- 인천 도착편 사용자는 지연·결항 푸시와 운항 정보 카드를 더 받지 못한다.
- 도착 시각 추정은 인천 출발이 지연됐을 때만 바뀐다.
- 마이그레이션의 삭제는 한 번만 정리한다. 이후 출발 공항을 인천에서 다른 곳으로 바꾼 교통편의 운항 상태 행은 갱신 없이 남는다. 클라이언트(출발 공항으로 provider 선택)와 안내 Edge(인천만 처리)가 읽지 않아 무해하다.

## 검증 기준

- 인천 출발이 아닌 편은 조회 대상이 아니고 감시에서 제외된다.
- 인천 출발편의 같은 날 편이 없으면 다른 날 편으로 대체하지 않는다.
- 지연 분만큼 도착 시각이 늦춰지고, 지연이 아니거나 결항·회항이면 입력값 그대로다.
- 도착 시각이 없는 교통편은 도착 시각을 만들지 않는다.
