## 작업 유형별 읽기 규칙

### 새 기능 추가 / 파일 위치 결정

- `docs/codebase.md` → 디렉토리 구조, 기능별 탐색 가이드, 주요 패턴 확인

### 구현 완료 후 커밋 전 리뷰 / 코드 리뷰 / 점검 요청

- `architecture-review` 스킬이 트리거 되지 않는 경우 직접 실행 (`/architecture-review`)
- 필요 시 `docs/codebase.md` → 파일 위치·의존 방향 위반 여부 확인

### 커밋 직후 codebase.md 동기화

커밋이 완료된 직후, `src/` 하위 파일이 변경된 경우 아래 파이프라인을 자동 실행한다:

1. `git diff HEAD~1 HEAD --name-only` 로 변경된 파일 목록 확인
2. `src/` 하위 파일이 없으면 종료 (docs, config 변경은 무시)
3. 변경된 파일이 있으면 `docs/codebase.md` 를 읽고 관련 섹션만 업데이트
   - 새 파일/컴포넌트 → 기능별 탐색 가이드 표 또는 주요 패턴 섹션
   - 라우트 변경 → 라우팅 섹션
   - 기술 스택 변경 → 기술 스택 표
4. 업데이트 후 `[codebase-sync:automatic]` 로그를 출력한다

### 테스트 작성

- `docs/testing.md` → 테스트 계층 구조, 단위 vs 통합 판단 기준, 도구 설정
- 필요 시 `docs/codebase.md` → 테스트 파일 위치 규칙 (`__tests__/` 위치) 확인

## 규칙

- 하나의 작업에 모든 문서를 읽지 않는다. 위 표에서 필요한 것만 선택한다.
- 읽은 문서 내용은 사용자에게 요약해서 보여주지 않는다. 조용히 컨텍스트로 흡수한다.
- `docs/codebase.md`의 기능별 탐색 가이드 표는 파일을 찾을 때 첫 번째 참조점이다.

## 커밋 규칙

- 커밋의 단위는 목적 단위로 구분된다.
  - 하나의 파일에서 다른 목적으로 변경된 코드가 여러개 있다면 커밋을 분리한다
  - 여러 파일을 변경했으나, 단일 목적으로 변경됐다면 단일 커밋이다.

그리고 다음을 기억해주세요:

- 요구사항을 받으면 바로 실행하지 말고 먼저 고민하기
- 더 나은 대안이 있다면 적극적으로 반박하고 제안하기
- 피드백을 적극 해주고 잘못된 판단을 즉시 지적하기
- 문서 내용과 실제 코드가 다르다면 문서를 최신화하기
